Konteks

Apa yang saya kerjakan, dan apa yang tidak saya tampilkan

Selama 6 bulan magang, peran utama saya adalah manual tester: menguji fitur aplikasi web layanan publik dan versi mobile-nya, menjalankan UAT di beberapa peran pengguna, melaporkan bug, lalu mengetes ulang setelah perbaikan. Pengujian performa dan keamanan saya kerjakan sesuai arahan PIC, jadi levelnya dasar.

Di magang, test case dan laporan saya tulis di spreadsheet yang dipakai bersama tim. Saya tidak memakai Jira di sana, jadi pengalaman Jira dan automation saya dapatkan dari project E-Learning, aplikasi web Laravel yang saya kembangkan bersama seorang teman.

Catatan kerahasiaan
  • Nama sistem, URL, dan data pengguna dari magang tidak ditampilkan.
  • Rincian temuan keamanan tidak dipublikasikan.
  • Dokumen asli magang bersifat internal, jadi contoh di bawah adalah versi yang disamarkan.

Pengalaman magang sebagai QA

Aplikasi web dan mobile layanan publik, Juli sampai Desember 2024
  • 1
    Functional dan exploratory testing Magang

    Menguji 18 area fitur dengan skenario positif dan negatif (±32 skenario), membandingkan hasil aktual dengan expected result. Versi mobile saya uji sebagai pengguna umum.

  • 2
    UAT lintas peran Magang

    Menyusun dan menjalankan 50 baris test case di spreadsheet bersama untuk peran pengguna, admin review, admin, dan super admin. Cakupannya termasuk alur laporan, pesan, notifikasi email, dan keamanan akun (reCAPTCHA, paksa ganti password).

  • 3
    Bug reporting dan retesting Magang

    Melaporkan bug langsung kepada PIC, lalu mengetes ulang perbaikan bug dan fitur baru. Contoh temuan: notifikasi email tidak terkirim, terlihat di UAT tiga peran sekaligus.

  • 4
    Performance testing dengan JMeter Magang Dasar

    Menjalankan load test dan stress test sesuai parameter dari PIC pada versi web, dan sekali pada versi mobile lewat emulator. Membaca Aggregate Report (response time, throughput, error rate) dan menulis kesimpulannya di laporan bulanan.

  • 5
    Vulnerability scanning dengan OWASP ZAP Magang Dasar

    Menjalankan automated scan pada versi web (hasil: tanpa temuan high, 7 medium, 7 low) dan sekali pada versi mobile, lalu merangkum temuan berdasarkan tingkat risiko. Ini scan otomatis, bukan penetration test.

  • 6
    API testing dengan Postman Magang

    Memverifikasi endpoint REST API pada aplikasi web lain untuk memastikan setiap endpoint merespons sesuai yang diharapkan. Pengujian yang lebih terdokumentasi ada di project E-Learning di bawah.

  • 7
    Monitoring layanan (tugas tambahan) Magang

    Memantau status server dan layanan beberapa instansi dengan Uptime Kuma dan Grafana, mencatat insiden down beserta screenshot, dan memeriksa pemasangan sertifikat SSL pada daftar website instansi.

Yang saya pelajari dari JMeter

Membaca hasil pengujian performa dengan hati-hati

Pada salah satu pengujian, Aggregate Report menunjukkan error rate yang sangat tinggi. Dari situ saya menyimpulkan bahwa sebagian besar request gagal dan perlu diselidiki, bukan bahwa aplikasinya pasti lambat. Angka response time dan throughput baru bermakna kalau request-nya benar-benar berhasil.

Cara menelusurinya
  • Cek response code dan response message di Results Tree.
  • Pastikan konfigurasi request sudah benar.
  • Bandingkan dengan log aplikasi atau server.
